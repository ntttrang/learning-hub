How three apps become one platform

A single React app shell reads typed content packs. Each of the three current apps becomes a content pack conforming to one shared schema, so features built once (practice, SRS, exams, notes, themes) work for every subject.

Why this shape

All three apps already model the same ideas (Subject → Domain → Lesson/Lab/Question/Exam/Compare + progress, SRS, notes, themes). The only real differences are the stack and the content shapes.

Unify the shell + engines once, express every subject as data, and expansion becomes “write a content pack,” never “fork the app.”
Designed for continuous expansion

Three ways the platform grows

Expansion never means editing the core. You add a subject, register a content type, or register a learning tool — each is a self-contained plug-in the shell discovers automatically.

1

New subject

Drop a folder of typed content that satisfies the schema. It appears on the hub with progress, practice, and exams for free.

no core changes
2

New content type

Register a block or question renderer (e.g. video, flashcard, interactive diagram). Scoring & SRS pick it up via the registry.

registry entry
3

New learning tool

Register a mode (e.g. flashcards, cheat-sheets, AI tutor). It becomes an opt-in tab any subject can enable.
