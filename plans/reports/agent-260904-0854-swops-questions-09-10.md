- Installation script options (`.../install/install-script/`): `-y`, `-c <answer file>`, `--install-dir`/`--os-user` (default `redislabs`) etc., new-installs-only markers.
- rladmin reference index + `status` page: views databases/endpoints/modules/nodes/shards; `extra backups|rack_id|redis_version`, `issues_only`, `*node` marker, ROLE master/slave, endpoint ROLE = proxy policy single/all-master-shards/all-nodes.
- `rladmin cluster create` / `cluster join`: exact parameter lists (`name/username/password/license_file/rack_aware/rack_id`; `nodes/username/password/client_cert/replace_node/rack_id...`).
- `rladmin node maintenance_mode` + maintenance-mode doc: drain semantics, snapshot, quorum-only, yellow SHARDS, 0/0 display, `demote_node`, stacking caution, use for hardware/OS patching.
- `rladmin node remove` + remove-node doc: cluster migrates resources off before removal; `wait_for_persistence`; removed node needs uninstall/reinstall to rejoin; two-node cluster with replication cannot remove a node.
- `rladmin migrate` (shard/all_shards/all_master_shards/all_slave_shards/endpoint_to_shards `commit`), `rladmin bind ... policy ...`.
- Upgrade cluster doc: in-place vs rolling (extra-node / replace-node), prerequisites (rlcheck per node, no maintenance mode, upgrade databases to a target-supported version first, master node first, one node at a time), per-node verification, `rl_uninstall.sh`.
- `rladmin upgrade db` page: upgrades database Redis version/modules; `redis_version`, `preserve_roles`; cluster upgrade alone does not upgrade databases.
- Cluster license keys doc: trial 30 days / 4 shards incl. replicas, default trial license, UI path Cluster > Configuration > General > License, cannot return to trial, expired-license do/don't lists, 7-day default expiry alert.
- Certificates doc: self-signed autogenerated on first node and copied to joiners; types proxy/cm/api/syncer/metrics_exporter/data_internode_encryption/etc.; CA replacement; browser untrusted warning.
- Rack-zone awareness doc: rack/zone failure protection, primaries+replicas+endpoints on different racks, enable at creation (`rack_aware`, `rack_id`) or REST `PUT /v1/cluster/policy {rack_aware:true}` / `PUT /v1/nodes/<id> {rack_id}`, cannot be turned off after enabling, 3-node/3-rack guideline, db-level `PUT /v1/bdbs/<id> {rack_aware:true}`.
- Proxy policy doc: single (default) / all-master-shards (OSS Cluster API) / all-nodes (load balancers w/o DNS); `rladmin bind db db:1 endpoint 1:1 policy all-master-shards`; reapply after topology changes.
- Create database doc: UI quick database (name, memory limit, version, optional port/capabilities), REST `POST /v1/bdbs {name,type:"redis",memory_size}`.
- Schedule periodic backups doc: intervals 1/4/12/24 h; locations FTP/SFTP/local mount/S3/GCS/Azure Blob; output is compressed .gz RDB files importable into a database; storage access verified before enabling; `redislabs:redislabs` ownership.
- Replica Of doc: destination wipes and loads from source, ongoing sync with lag, statuses syncing/synced/sync stopped, restart = full resync, don't write to destination, disable Replica Of before failing clients over to destination, upgrade destination before source, max 32 sources, `rladmin tune db ... repl_backlog`.
